## Medication Error Cat B Quick Reporter

### Complete Implementation Master Prompt for Antigravity / Codex

You are a senior software engineer experienced with:

* Google Apps Script
* Google Sheets
* vanilla JavaScript
* HTML/CSS
* mobile-first healthcare applications
* medication safety workflow
* Git

* clasp
* maintainable internal hospital systems

Your task is to build a production-quality but intentionally simple internal hospital pharmacy web application called:

# CatchME

Meaning:

**ME = Medication Error**

Tagline:

# Catch ME before it reaches the patient.

The application is specifically designed to make Category B medication error reporting extremely fast.

Prioritize in this exact order:

**Reporting speed → Medication safety → Data integrity → Simplicity → Maintainability → Visual polish**

Do not optimize for feature count.

Do not over-engineer the project.

# 3. Product purpose

CatchME is an internal hospital pharmacy tool for rapidly recording:

# Medication Error Category B / Near Miss

For this application:

> A medication error has occurred, but the error was detected and corrected before reaching the patient.

Current workflow often requires:

```text
detect error
→ write briefly on paper
→ later re-enter the same information into the hospital risk management system
```

This duplicate workflow contributes to under-reporting.

CatchME should make reporting easier than writing the event on paper.

Target reporting time:

# 10–20 seconds per typical event

Ideal interaction:

```text
Open CatchME
→ tap microphone
→ speak one short sentence
→ review result
→ tap Save
```

# 4. Strict application scope

CatchME V1 is primarily a:

# Category B Quick Reporter

It is NOT a complete hospital incident reporting system.

For every valid Quick Report:

```text
severity = B
patient_reached = No
```

These values are system-controlled.

The reporter must NOT select Category A–I.

Do not build full A–I workflow in V1.

# 5. Category B safety gate

If the transcript indicates that the error may already have reached the patient, stop the normal Category B workflow.

Examples:

```text
จ่ายไปแล้ว
คนไข้ได้รับแล้ว
คนไข้กินแล้ว
พยาบาลให้ยาแล้ว
ให้ยาไปแล้ว
```

Show a blocking warning:

# เหตุการณ์นี้อาจไม่ใช่ Category B

Message:

```text
CatchME ใช้สำหรับเหตุการณ์ที่ยังไม่ถึงตัวผู้ป่วย
กรุณาตรวจสอบก่อนบันทึก
```

Do NOT silently save it as Category B.

If the user confirms that the event reached the patient:

```text
stop CatchME Quick Report flow
→ instruct user to use the hospital's normal risk-reporting process
```

However:

```text
วอร์ดเจอก่อนให้คนไข้
พยาบาลพบก่อนถึงผู้ป่วย
```

may still qualify as Category B.

# 35. Parser confidence

Use:

```text
High
Medium
Low
```

Do not show numeric confidence to normal reporters.

Suggested signals:

```text
explicit actor/stage      strong positive
explicit error keyword    strong positive
specific local subtype    positive
detected-stage clue       positive
actual + expected         positive
conflicting evidence      negative
multiple possible codes   clarification required
```

Suggested threshold:

```text
High >= 0.75
Medium 0.50–0.74
Low < 0.50
```

Equivalent consistent point scoring is acceptable.
